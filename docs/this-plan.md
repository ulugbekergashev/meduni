# MedUni AI Platform — Полный план разработки

**Назначение документа:** техническое задание для разработки в Claude Code. Документ самодостаточен: содержит архитектуру, модель данных, API, карту экранов, логику учебного процесса и порядок сборки.

**Редакция:** включены правки «Путь 3» — гибридная модель: платформа генерирует черновик → преподаватель обязательно проверяет и утверждает. Две блокирующие контрольные точки (конспект и утверждение контента) закреплены в модели данных, пайплайне и UI.

**Языки платформы:** узбекский (латиница) и русский, переключение в интерфейсе.
**Домен:** медицинский университет.

---

## 1. Видение

Единая веб-платформа университета, объединяющая два контура:

**Контур A — AI-генерация контента.** Преподаватель загружает материал по теме → система генерирует учебный комплект: презентация (редактируемый PPTX), озвученный видеоролик, тесты, клинический кейс. Всё заземлено на исходный материал, всё проходит утверждение преподавателем.

**Контур B — учебный процесс (LMS).** Студенты проходят темы последовательно (уроки открываются один за другим по правилам), сдают тесты и кейсы, отмечаются на занятиях (QR-посещаемость), зарабатывают XP и соревнуются в рейтингах. Преподаватели видят прогресс и аналитику. Админ управляет структурой университета.

Принципы: ничего не публикуется студентам без утверждения преподавателем; весь AI-контент опирается только на загруженные материалы; каждый предмет, курс, преподаватель и студент имеет свою страницу; mobile-first для студентов.

## 2. Роли

| Роль | Что делает |
|---|---|
| **Админ** | Структура университета (факультеты → кафедры → предметы, группы), пользователи, фирменный шаблон презентаций, глоссарий терминов, AI-квоты, аудит, аналитика по вузу |
| **Преподаватель** | Свои курсы: создаёт темы, загружает материалы, запускает генерацию, редактирует и утверждает контент, настраивает правила открытия уроков, ведёт посещаемость, видит прогресс группы. **Является автором и несёт ответственность за контент: AI-генерация даёт только черновик; публикует контент только преподаватель после проверки. Студенты контент не генерируют** |
| **Студент** | Проходит уроки последовательно, смотрит видео/презентации, сдаёт тесты и кейсы, сканирует QR на занятии, видит свой прогресс, XP и рейтинг |

Опционально в будущем: роль «заведующий кафедрой» (аналитика по кафедре, утверждение глоссария) — заложить в RBAC, не реализовывать в первой версии.

## 3. Архитектура системы

Модульный монолит + фоновые воркеры. Микросервисы не нужны на этом масштабе — они усложнят разработку без выгоды.

```
┌─────────────────────────────────────────────────────┐
│  Frontend: Next.js (React, TypeScript)              │
│  SSR + SPA, i18n (uz-Latn / ru), mobile-first       │
└──────────────┬──────────────────────────────────────┘
               │ REST + SSE (статусы генерации)
┌──────────────▼──────────────────────────────────────┐
│  Backend API: FastAPI (Python)                      │
│  Модули: auth, org, courses, content, learning,     │
│  attendance, gamification, admin, export            │
└───┬──────────────┬───────────────────┬──────────────┘
    │              │                   │
┌───▼────┐   ┌─────▼─────┐   ┌─────────▼─────────────┐
│Postgres│   │ Redis     │   │ Celery Workers        │
│        │   │ (queue,   │   │ - parse_worker (doc)  │
│        │   │  cache)   │   │ - llm_worker          │
└────────┘   └───────────┘   │ - image_worker        │
                             │ - tts_worker          │
┌────────────┐               │ - video_worker(ffmpeg)│
│ S3-storage │◄──────────────┴───────────────────────┘
│ (MinIO)    │
└────────────┘
        AI-слой: адаптеры провайдеров (см. 5.4)
```

**Ключевые компоненты:**
- `api/` — FastAPI, синхронные операции (CRUD, авторизация, отдача контента).
- `workers/` — длинные задачи: парсинг документов, LLM-вызовы, генерация изображений, TTS, сборка видео ffmpeg. Каждая генерация — цепочка Celery-задач с сохранением промежуточных результатов.
- `web/` — Next.js фронтенд.
- PostgreSQL — вся реляционная модель; JSONB для слайдов, вопросов, конспектов.
- MinIO (S3) — файлы: исходники, PPTX, MP4, аудио, изображения.
- SSE (Server-Sent Events) — фронтенд подписывается на прогресс генерации (`parsing → digest → slides → images → tts → video`).

## 4. Модель данных

### 4.1 Организационная структура

- **User**: id, role (admin/teacher/student), full_name, email, phone, password_hash, locale (uz/ru), avatar_url, is_active.
- **Faculty**: id, name_uz, name_ru.
- **Department** (кафедра): id, faculty_id, name_uz, name_ru.
- **Subject** (предмет): id, department_id, name_uz, name_ru, description. У предмета — своя публичная страница.
- **StudentGroup**: id, faculty_id, name, year_of_study.
- **Course** (поток = предмет + семестр + группа(-ы) + преподаватель): id, subject_id, teacher_id, semester, academic_year, groups[m2m], settings_json (правила открытия по умолчанию). У курса — своя страница.
- **Enrollment**: student_id, course_id, status.
- **TeacherProfile**: user_id, department_id, position, bio. У преподавателя — своя страница со списком его курсов.

### 4.2 Контент и генерация

- **Topic** (тема/урок): id, course_id, title_uz, title_ru, order_index, unlock_rule_json (см. 6.2), status (draft/published).
- **SourceMaterial**: id, topic_id, file_url, file_type, uploaded_by, parsed_text_url, parse_status.
- **TopicDigest** (конспект темы): id, topic_id, digest_json (цели обучения, концепции, термины uz/ru, факты, дозировки, описания иллюстраций), version, approved_by_teacher (bool). Единый источник для всех генераций. **Переход к генерации презентации/видео/теста/кейса невозможен, пока `approved_by_teacher = false`: конспект — первая контрольная точка преподавателя, ещё до любой генерации.**
- **GenerationJob**: id, topic_id, kind (digest/presentation/video/quiz/case), status, steps_json (прогресс по шагам), cost_estimate, tokens_used, error, created_by.
- **ContentItem** (базовая сущность): id, topic_id, kind, language (uz/ru), status (**draft → review → approved → published**), approved_by, approved_at, version. **Поля аудита проверки: reviewed (bool), review_opened_at (проверка, что преподаватель реально открывал редактор), edited_by_teacher (bool — были ли ручные правки), factcheck_flags_resolved (bool — все ли подсвеченные несоответствия обработаны).**
- **Presentation**: content_item_id, slides_json (заголовки, тезисы, заметки, ссылки на изображения), pptx_url, template_id.
- **Video**: content_item_id, script_json (текст озвучки по слайдам), audio_url, mp4_url, srt_url, duration_sec, voice_id.
- **Quiz**: content_item_id, settings (кол-во, сложность, порог прохождения %, число попыток); **Question**: quiz_id, text, options_json, correct_index, explanation_json (объяснение каждого дистрактора), difficulty (recall/understand/apply), source_fragment (привязка к исходнику).
- **ClinicalCase**: content_item_id, case_json (жалобы, анамнез, объективно, лаборатория, вопросы, эталонный разбор), format (short/extended).
- **Glossary**: id, department_id, term_ru, term_uz, term_lat, approved. Подставляется в каждый LLM-промпт.
- **PresentationTemplate**: id, name, pptx_master_url, colors_json, logo_url (управляется админом).

### 4.3 Учебный процесс

- **LessonSession** (занятие по расписанию): id, topic_id, course_id, starts_at, room, attendance_open (bool), qr_secret (ротация).
- **Attendance**: session_id, student_id, status (present/late/absent/excused), method (qr/manual), marked_at.
- **Progress**: student_id, topic_id, state (locked/available/in_progress/completed), video_watched_pct, completed_at.
- **QuizAttempt**: quiz_id, student_id, answers_json, score_pct, passed, attempt_no, started_at, finished_at.
- **CaseAttempt**: case_id, student_id, answers_json, teacher_feedback, score.

### 4.4 Геймификация

- **XPEvent**: student_id, course_id, kind (lesson_completed/quiz_passed/quiz_perfect/case_submitted/attendance/streak_bonus), points, created_at.
- **StudentStats**: student_id, course_id, total_xp, current_streak_days, best_streak.
- **Badge**: id, code, title_uz/ru, icon, rule_json; **StudentBadge**: student_id, badge_id, earned_at.
- Лидерборды не хранятся — вычисляются (materialized view / Redis-кэш) по группе, курсу, факультету за период (неделя / семестр).

### 4.5 Служебные

- **AuditLog**: actor_id, action, entity, entity_id, payload_json, ts. Логируются: утверждения контента (**кто, когда, были ли ручные правки, сколько флагов фактчека было и как каждый обработан**), ручные правки посещаемости, изменения оценок.
- **AIUsage**: department_id, month, tokens, images, tts_chars, cost — для квот в админке.

## 5. Контур A: AI-генерация

### 5.1 Пайплайн

Пайплайн содержит **две обязательные блокирующие остановки**: после конспекта и после генерации. Ни одна из них не проходится автоматически.

```
Файл → parse_worker (текст+структура; OCR для сканов)
     → llm_worker: TopicDigest (structured JSON)
     ▓▓ ОСТАНОВКА 1 (блокирующая): преподаватель редактирует и утверждает
     ▓▓ конспект (approved_by_teacher = true). Без этого генерация ниже
     ▓▓ недоступна.
     → параллельно из конспекта:
        ├─ Quiz + ClinicalCase (llm_worker)
        ├─ Presentation: slides_json → image_worker (иллюстрации)
        │                → рендер PPTX (python-pptx, шаблон вуза)
        └─ Video: сценарий → tts_worker → video_worker (ffmpeg:
           слайды PNG + аудио + тайминги + SRT + интро/аутро)
     → всё в статус review
     ▓▓ ОСТАНОВКА 2 (блокирующая): преподаватель открывает каждый артефакт,
     ▓▓ правит и утверждает (review → approved — только явным действием).
     → published
```

### 5.2 Модели

| Задача | Модель | Примечание |
|---|---|---|
| Конспект, слайды, тесты, кейсы, сценарии | Claude Sonnet 4.6 или Gemini | Structured output (JSON Schema). До фиксации — сравнительный тест на узбекском медицинском контенте |
| Фактчек | Тот же LLM, отдельный проход | Сверка результата с исходником; несовпадения подсвечиваются преподавателю |
| Иллюстрации, схемы | Nano Banana Pro (gemini-3-pro-image); младшая Nano Banana для простых картинок | Мультиязычный текст на изображениях |
| TTS uz/ru | Aisha AI или Azure (uz-UZ-Madina/Sardor, ru-RU) | Тест на медицинской терминологии; латиница с апострофами oʻ/gʻ |
| Сборка видео | ffmpeg | Генеративные видеомодели не используются |

### 5.3 Правила качества (обязательные)

1. LLM генерирует **только из загруженного материала**; запрет на добавление фактов, дозировок, протоколов «из головы» — в системном промпте каждого вызова.
2. Глоссарий кафедры подставляется в каждый промпт для консистентной терминологии.
3. Фактчек-проход после каждой генерации; помеченные утверждения показываются преподавателю с подсветкой.
4. Публикация невозможна без статуса approved. В каждом артефакте — «Проверено: ФИО, дата».
5. **Ни один артефакт не переходит в статус published автоматически. Система всегда останавливается на review; переход в approved — только явным действием преподавателя. Массовое «утвердить всё без просмотра» запрещено на уровне UI: нельзя утвердить контент, который ни разу не открывали (контроль через reviewed / review_opened_at).**

### 5.4 AI-слой как адаптеры

Пакет `ai/` с интерфейсами `TextModel`, `ImageModel`, `TTSModel` и реализациями по провайдерам. Выбор провайдера — конфигурацией. Это защита от смены цен/качества провайдеров: замена без переписывания бизнес-логики.

## 6. Контур B: учебный процесс студента

### 6.1 Последовательное открытие уроков

Темы курса упорядочены (`order_index`). Состояния для студента: `locked → available → in_progress → completed`. Следующая тема открывается при выполнении правила завершения предыдущей.

### 6.2 Правила открытия (unlock_rule_json, настраивает преподаватель)

Конструктор условий (И/ИЛИ):
- просмотр видео ≥ N% (default 80),
- тест сдан с результатом ≥ N% (default 70), максимум M попыток,
- кейс отправлен (и/или проверен преподавателем),
- присутствие на занятии по теме (связь с Attendance),
- дата: тема не раньше конкретной даты (синхронизация с расписанием),
- ручное открытие преподавателем (override для отдельного студента — уважительная причина).

Default-правило задаётся на уровне курса, переопределяется на уровне темы.

### 6.3 Прохождение темы студентом

Страница урока — единый плеер темы: видео → презентация (просмотр в браузере + скачивание PPTX/PDF) → тест → кейс. Прогресс-бар по элементам. После завершения — экран результата: XP, открытие следующей темы, позиция в рейтинге.

## 7. Геймификация

**XP:** завершение урока +50; тест сдан +30; тест на 100% +20 бонус; кейс отправлен +40; присутствие на занятии +10; стрик 5 учебных дней подряд +25. Значения — в конфиге, правится админом.

**Стрики:** дни подряд с любой учебной активностью. Отображение: огонёк + счётчик.

**Бейджи (rule_json):** «Первая тема», «Серия из 5 тестов без пересдач», «100% посещаемость месяца», «Тема раньше всех в группе», «Марафонец» (стрик 14) и т.п. Набор расширяемый.

**Лидерборды:** внутри группы (основной), по курсу, по факультету; периоды — неделя и семестр. Важно: рейтинг показывает топ-10 + позицию самого студента («вы 18-й из 54»), чтобы не демотивировать нижнюю часть списка. В настройках профиля студент может скрыть своё имя в публичных рейтингах (показывается анонимно) — соревнование должно мотивировать, а не давить.

**Прогресс курса:** карта тем в виде «пути» (path) с пройденными/текущей/закрытыми темами — визуально как маршрут, это сильный мотиватор в мобильном интерфейсе.

## 8. Посещаемость (явка)

**Основной сценарий — динамический QR:**
1. Преподаватель на занятии открывает сессию (LessonSession) → на его экране/проекторе QR-код, обновляющийся каждые 15 секунд (TOTP-подобный секрет) — скриншот от одногруппника не сработает.
2. Студент в своём кабинете нажимает «Отметиться» → сканирует QR → Attendance(present). Опоздание фиксируется автоматически по времени (порог настраивается).
3. Преподаватель видит live-список отметившихся, вручную правит (absent/excused); все ручные правки — в AuditLog.

**Отчёты:** журнал по курсу (таблица студенты × занятия), сводка по студенту, экспорт XLSX для кафедры. Посещаемость участвует в правилах открытия тем и в XP.

## 9. UX/UI — карта экранов

Дизайн-система: единая библиотека компонентов, переключатель uz/ru в шапке, светлая тема (тёмная — later), студенческий интерфейс проектируется mobile-first, преподавательский и админский — desktop-first.

### 9.1 Публичные / общие
- `/login` — вход (email/телефон + пароль); регистрации нет — пользователей создаёт админ (импорт из XLSX).
- `/subjects/{id}` — страница предмета: описание, кафедра, преподаватели, курсы.
- `/teachers/{id}` — страница преподавателя: фото, кафедра, должность, его предметы и курсы.

### 9.2 Студент
- `/app` — дашборд: «Продолжить обучение» (текущая тема), мои курсы с прогресс-барами, стрик, ближайшие занятия, позиция в рейтинге недели.
- `/app/courses/{id}` — страница курса: карта тем («путь» с замками), преподаватель, моя статистика по курсу, рейтинг группы.
- `/app/topics/{id}` — страница урока: плеер видео (с сохранением позиции и % просмотра), вкладка «Презентация», вкладка «Тест» (таймер опционально, мгновенный результат, разбор ошибок с объяснениями дистракторов после закрытия попыток), вкладка «Кейс» (условие → поля ответов → после проверки эталонный разбор).
- `/app/rating` — лидерборды: группа / курс / факультет, неделя / семестр.
- `/app/profile` — профиль: XP, бейджи, стрики, настройки языка и приватности рейтинга.
- `/app/attendance` — «Отметиться» (сканер QR) + моя посещаемость.

### 9.3 Преподаватель
- `/teach` — дашборд: мои курсы, задачи («3 кейса ждут проверки», «контент темы 5 ждёт утверждения»), ближайшие занятия с кнопкой «Открыть посещаемость».
- `/teach/courses/{id}` — страница курса: список тем (drag-and-drop порядок), статусы контента по каждой теме (значки: презентация/видео/тест/кейс × draft/review/approved), сводный прогресс группы (heatmap студенты × темы), настройки правил открытия.
- `/teach/topics/{id}` — **конструктор темы**, центральный экран платформы:
  1. Материалы: загрузка файлов, статус парсинга.
  2. Конспект темы: редактируемый структурированный конспект, кнопка «Утвердить конспект».
  3. Генерация: чекбоксы (презентация / видео / тест / кейс), язык(и), параметры теста → «Сгенерировать» → live-прогресс по шагам (SSE). Блок недоступен, пока конспект не утверждён.
  4. Редакторы результатов: слайды (правка текста тезисов, перегенерация отдельной иллюстрации, скачать PPTX), видео (правка сценария → переозвучка → пересборка; предпросмотр), тест (правка вопросов/вариантов/объяснений, добавление своих вопросов), кейс (правка блоков).
  5. Подсветка фактчека: утверждения, не найденные в исходнике, выделены — «подтвердить» или «исправить».
  6. Кнопка «Утвердить и опубликовать». **Неактивна, пока: конспект не утверждён, остались необработанные флаги фактчека, или контент ни разу не открывался в редакторе. Рядом — чеклист готовности (что осталось сделать).**
- `/teach/sessions/{id}` — экран занятия: большой QR (для проектора), live-список отметившихся, ручные правки.
- `/teach/courses/{id}/gradebook` — журнал: посещаемость + результаты тестов + кейсы, экспорт XLSX.
- `/teach/cases/review` — очередь кейсов на проверку: ответ студента, поля фидбека и балла.

### 9.4 Админ
- `/admin` — дашборд вуза: активность, расход AI по кафедрам, топ-контент.
- `/admin/structure` — факультеты → кафедры → предметы; группы; импорт студентов/преподавателей из XLSX.
- `/admin/users` — пользователи, роли, сброс паролей.
- `/admin/courses` — создание курсов (предмет + преподаватель + группы + семестр).
- `/admin/templates` — шаблоны презентаций (загрузка мастер-PPTX, цвета, логотип).
- `/admin/glossary` — глоссарий терминов по кафедрам (таблица ru/uz/lat, импорт XLSX).
- `/admin/ai` — квоты по кафедрам, расход, выбор провайдеров, конфиг XP.
- `/admin/audit` — журнал действий.

## 10. API — структура обмена

REST, префикс `/api/v1`, JWT (access + refresh), RBAC-middleware по ролям. Ответы — JSON; ошибки — единый формат `{error: {code, message_uz, message_ru}}`.

```
AUTH      POST /auth/login, /auth/refresh, /auth/logout
ORG       CRUD /faculties /departments /subjects /groups /users
          POST /users/import (XLSX)
COURSES   CRUD /courses; GET /courses/{id}/students /progress
TOPICS    CRUD /topics; PATCH /topics/reorder; PUT /topics/{id}/unlock-rule
MATERIALS POST /topics/{id}/materials; GET /materials/{id}/status
DIGEST    GET/PUT /topics/{id}/digest; POST /topics/{id}/digest/approve
GENERATE  POST /topics/{id}/generate {kinds[], languages[], params}
          GET  /jobs/{id}  |  SSE /jobs/{id}/stream
CONTENT   GET/PUT /content/{id}; POST /content/{id}/approve /publish
          POST /presentations/{id}/regenerate-image/{slide}
          POST /videos/{id}/rebuild
LEARNING  GET /me/courses /me/topics/{id}; POST /me/topics/{id}/video-progress
          POST /quizzes/{id}/attempts; PUT /attempts/{id}/answers; POST /attempts/{id}/finish
          POST /cases/{id}/attempts; POST /case-attempts/{id}/review (teacher)
ATTEND    POST /sessions; POST /sessions/{id}/open; GET /sessions/{id}/qr (ротация)
          POST /attendance/checkin {qr_token}; PATCH /attendance/{id}
GAMIF     GET /me/stats /me/badges; GET /leaderboards?scope=&period=
EXPORT    GET /quizzes/{id}/export?format=moodle_xml|gift|pdf
          GET /courses/{id}/gradebook.xlsx
ADMIN     /admin/ai-usage /admin/quotas /admin/templates /admin/glossary /admin/audit
```

Серверные инварианты контрольных точек: `POST /topics/{id}/generate` возвращает ошибку, пока конспект не утверждён; `POST /content/{id}/approve` — пока не выполнены reviewed / factcheck_flags_resolved; `POST /content/{id}/publish` — пока статус не approved. Проверки дублируются на бэкенде, а не только в UI.

## 11. Технологический стек

- **Frontend:** Next.js 15 + TypeScript, TailwindCSS, TanStack Query, next-intl (uz-Latn/ru), Zod.
- **Backend:** Python 3.12, FastAPI, SQLAlchemy 2 + Alembic, Pydantic v2.
- **Очереди:** Celery + Redis; SSE для прогресса.
- **БД:** PostgreSQL 16 (JSONB для слайдов/вопросов/конспектов).
- **Файлы:** MinIO (S3 API) — исходники, PPTX, MP4, SRT, изображения.
- **Документы:** python-pptx (рендер PPTX), pypdf/docx-парсеры, Tesseract/vision-LLM для сканов.
- **Видео:** ffmpeg в контейнере воркера.
- **AI:** пакет адаптеров (Anthropic SDK, Google GenAI SDK, TTS-провайдер).
- **Инфраструктура:** Docker Compose (dev) → docker-compose/k8s на сервере вуза или VPS; Nginx; резервное копирование Postgres + MinIO ежедневно.
- **Наблюдаемость:** structured logging, Sentry, метрики затрат AI в AIUsage.

## 13. Нефункциональные требования

- **Безопасность:** RBAC на каждом эндпоинте; студент видит только опубликованный контент своих курсов; rate-limit на попытки теста; подписанные (presigned) ссылки на файлы; QR-токены одноразовые с TTL.
- **Персональные данные:** минимум ПД; пароли argon2; аудит доступа к оценкам; уточнить требования к размещению данных в Узбекистане (см. открытые вопросы).
- **Прослеживаемость контента:** каждый опубликованный артефакт хранит снимок «на чём основан» — ссылку на исходный материал и версию конспекта. Для медицины это критично: если через полгода найдут ошибку, видно, из какого источника она пришла.
- **Производительность:** страница урока < 1 с (кэш контента); генерация комплекта — минуты (асинхронно, пользователь не ждёт на экране); одновременные генерации ограничены очередью и квотами.
- **Отказоустойчивость генерации:** каждая ступень пайплайна идемпотентна и перезапускаема; частичный результат сохраняется (упал TTS — слайды не теряются).
- **Тесты:** unit на unlock-правила, XP-начисление, QR-валидацию, блокировки контрольных точек (нельзя генерировать без утверждённого конспекта, нельзя утвердить неоткрытый контент); интеграционные на пайплайн генерации с мок-провайдерами; e2e на критический путь студента.

## 14. Порядок сборки (по зависимостям, без сроков)

Milestone = связный работающий срез. Каждый следующий строится на предыдущем.

**M1 — Фундамент.** Monorepo, Docker Compose, Postgres+Redis+MinIO, auth (JWT, RBAC), модель орг-структуры, админка структуры и пользователей (+импорт XLSX), i18n-каркас uz/ru. *Готово, когда: админ создал факультет→кафедру→предмет→курс→группу, преподаватель и студент видят свои пустые кабинеты.*

**M2 — Ядро контента.** Темы курса, загрузка материалов, parse_worker, TopicDigest (генерация + редактор + утверждение), GenerationJob + SSE-прогресс, AI-слой адаптеров, глоссарий. *Готово: преподаватель загрузил PDF и получил редактируемый конспект на uz/ru.*

**M3 — Тесты и кейсы.** Генерация Quiz и ClinicalCase из конспекта, редакторы, фактчек-подсветка, workflow утверждения, экспорт Moodle XML/GIFT/PDF. *Готово: утверждённый тест и кейс по реальной теме кафедры.*

**M4 — Презентации.** slides_json → python-pptx по шаблону вуза, image_worker (Nano Banana Pro), редактор слайдов, перегенерация отдельной иллюстрации, шаблоны в админке. *Готово: скачиваемый брендированный PPTX.*

**M5 — Видео.** Сценарий озвучки, tts_worker (uz-Latn/ru), video_worker (ffmpeg: слайды+аудио+SRT+интро), предпросмотр, пересборка после правок сценария. *Готово: MP4 с субтитрами по реальной теме.*

**M6 — Студенческий контур.** Страницы курса и урока, видеоплеер с трекингом %, прохождение тестов (попытки, разбор ошибок), сдача кейсов + очередь проверки у преподавателя, Progress и unlock-правила (конструктор условий), страницы предмета/преподавателя. *Готово: студент прошёл тему и открыл следующую.*

**M7 — Посещаемость и геймификация.** LessonSession + динамический QR + чек-ин, журнал и экспорт; XP-события, стрики, бейджи, лидерборды, карта-«путь» курса, связь посещаемости с unlock-правилами. *Готово: живое занятие с QR; рейтинг недели в группе.*

**M8 — Аналитика и полировка.** Дашборды преподавателя (heatmap прогресса) и админа (расход AI, активность), квоты, аудит, Sentry, бэкапы, нагрузочный прогон, пилот на 1–2 кафедрах.

Правило работы в Claude Code: один milestone — одна ветка/серия PR; после каждого milestone обновлять CLAUDE.md и docs/decisions.
